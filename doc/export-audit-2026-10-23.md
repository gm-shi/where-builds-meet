# 导出数据核验，2026 年 10 月 23 日

## 证据与范围

将整理后的实现与
`local/datamine/2026-10-23_02-31-51-671_+0100-hJTWej` 进行了比较，随后将全部十六个
导出文件与 10 月 21 日 16:50 的快照进行了结构比较。本地导出数据是
证据，而非运行时依赖。

十五个文件在结构上完全相同，包括原始增益/被动、心法、
武学天赋、套装、装备、养成、奇术和
机关。只有 `wwm-skills-normal-all.json` 发生了变化。其中仅有的变化记录
是 20603005、20603102、20603103、20603201 以及 20603202–20603205；所有变化
都位于 `timings` 内。技能系数、固定伤害、冷却、描述
以及其他技能记录在这两份快照之间均未变化。

这核验了所有流派完整的导出差异。它**并不**
确立每个流派从来源到运行时的完整一致性。导出未变化、
已有秒伤基线，或系数与另一条记录一致，都不能证明
路线归属、效果适用条件或事件顺序是正确的。现有的
有意排除项以及经用户确认的数值例外仍然有效。
初次审计没有改动任何计算或战斗数据。其后
应用户要求实现的开场接伞策略记录在下文。已接受的秒伤
快照在数值审核之前保持不变。

直接命中时钟与未强化的下一次投掷关卡在浮点
精度内一致。重要的不一致在于辅助事件：

1. **幻影伞生成与其共鸣被合并。**
   `PhantomUmbrellaSummon` 替换幻影伞并立即触发
   `Resonance`。每个阶段都在回程直接命中时调度该辅助技能。
   导出数据为生成以及其后的共鸣请求分别给出了独立的
   时钟。T6 仍然给予每次投掷的召唤；适用条件规则并不是
   时机差异所在。
2. **接伞效果在衔接关卡处结算。**
   `EverspringPerfectCatch` 与下一阶段具有相同的编写 `time`。
   `queueTime` 会更早接纳排队的触发器，但并不会在那里执行接伞：
   时间轴根据 `action.time` 计算目标开始时间。导出数据
   使接伞共鸣、落花以及芳歌的获得发生在窗口内被接受的输入时刻，
   与下一次投掷的开始时间无关。在关闭边界处成功接伞仍属于
   允许的情况；仅凭导出数据无法选定玩家的输入时间。
3. **强化接伞窗口并非普通窗口的统一缩放。**
   当芳歌生效时，运行时将所有阶段时钟按 `1 / 1.3` 缩放。
   这能重现强化后的直接命中和衔接关卡，但无法重现
   强化接伞窗口的开启时刻：

   | 阶段 | 当前缩放后的排队开启 | 导出的强化接伞开启 | 导出的强化关闭 / 下一次开始 |
   | ---- | -------------------- | ------------------ | --------------------------- |
   | 1    | 0.473373             | 0.295858           | 0.828402                    |
   | 2    | 0.320513             | 0.252564           | 0.737179                    |
   | 3    | 0.419580             | 0.349650           | 0.839161                    |
   | 4    | 0.349650             | 0.279720           | 0.769231                    |

4. **就绪状态与伤害效果清理的生命周期不同。**
   导出数据区分了在投掷期间被消耗的加速就绪状态、
   绑定动作的激活标记，以及在强化衔接关卡处移除的伤害效果。
   运行时在投掷开始时消耗 `FragrantSong`，并使用
   单独的两秒 `FragrantSongResonance` 标记，由后续投掷
   清除/重新预备。预期的归属与用户的规则一致：
   芳歌强化该次投掷及该次投掷的共鸣。仅凭归属
   并不能验证来源中在打断和终点处的显式清理。
5. **缺少作为显式机制的延迟首次接伞处理。**
   导出数据允许在没有可用幻影伞时的接伞设置一个待定标记，
   并在之后的生成共鸣请求处检查。这是该次接伞立即请求的
   替代方案，而不是额外的无条件脉冲。
   当前的接伞只在执行时检测 `PhantomUmbrella` 是否存在。

不要将导出数据中单独标注的**未连接共鸣请求**
计为额外的必定命中：导出数据明确将目标可用性
留作未定。同样，共鸣请求并不自动证明其
伤害接触的时间戳。修复时必须保留这些区别。

当前的 14 次投掷循环并不会仅因这些发现而被否定：
下一次开始的关卡仍然一致。共鸣时机、落花时机、
芳歌的可用性以及效果覆盖需要重建时间轴才能
衡量其对伤害的影响。此前仅移动气竭的实验
并未涉及这些修正。

## 验证

### 已实现的开场接伞策略

试验之后，用户要求更新时间表并采用 87 次共鸣命中。
生产数据现在将生成/请求时机分离，使用导出的普通
与强化开启输入，并对无幻影伞的延迟接伞只结算一次。
现有的衔接关卡保持不变。已被接纳的投掷即使在葬花到期后
也会完成其接伞；只有再接纳另一次投掷才受该效果的限制。
这正是每批额外多出最后一次接伞的确切边界，
而不是声称每个最后输入都落在到期之前。

已实现的基准测试重现了下表中的开场接伞列：破阵 18 下
100% 幻鸣为 69,449.526 秒伤，共鸣命中 87 次，红消香断直接命中 84 次。
常规为 89 次共鸣命中。修改前后的生产数据包保留了相同的
投掷开始时间戳与编写的真气标记。归属测试验证了
提前获得芳歌的接伞无法将芳歌给予其当前的普通投掷。

`npm run build` 通过，包括全部 287 个普通测试文件 / 1,632 项测试、
TypeScript、本地化检查和 Vite。`npm run lint` 通过，存在于无关 UI 文件中的
既有 array-index-key 警告。针对性的基准测试和尘
机制测试通过。秒伤防护报告十二个尘用例发生变化，其他
流派无失败；确切的拟议秒伤/总伤害数值记录在
`dps-snapshots.md` 中，未刷新已接受的快照 JSON。

### 隔离的尘时机试验

使用内存中的技能/效果变体重建生产计算数据包，
采用全承音小外配装及所提供的基准测试覆盖值：食物后有效外功攻击
最小值 2918、破竹 360–806 加 68 无相、
牵丝 44、精准 133.8%、会心 147.9%、会意 19.1%、直接会心
4.6%、绳舟行木 T5 之前的 45.8 外功穿透，以及 25% 醉梦游春武学
定音。其余加成取自配装模板。四个 T6 心法
为千营一呼、绳舟行木、易水歌和所恨年年。选择了天工·火、
外功攻击食物和鬼掣帖。

在不改动生产数据的情况下测试了两种部分时机变体：

- 分离按来源计时的幻影伞生成与生成共鸣请求，
  保留现有的窗口关闭时接伞策略。投掷本地的生成标记
  确保较低重数的节奏不会发出无条件的每次投掷脉冲。
- 相同的分离，并在普通/强化窗口开启时接受接伞。
  没有幻影伞的待定接伞在之后的请求处结算；
  它不会再额外发出立即的接伞脉冲。现有的衔接
  关卡、芳歌归属规则以及编写的真气标记均保持不变。

| 常规      | 18   | 69092.6744455861  | 69098.13563287197         | 69802.6824118557       |

对于破阵 18 的 100% 幻鸣，分离生成/请求使秒伤变化
+0.00446%；接受提前接伞使其变化 +0.95643%。提前接伞
变体保留全部 84 次红消香断直接命中，但将共鸣总命中次数
从 84 提高到 87：每批可多容纳一次最后的接伞。常规同样
从 86 次变为 89 次共鸣命中。这些替代方案都无法弥合与
所提供的 66,800 平均秒伤之间的差距，也都无法重现截图中的 83

该试验检查了普通/强化投掷的来源请求偏移、保留的

没有幻影伞时，首次投掷在请求处的两次脉冲（生成加延迟
接伞）。所有检查均通过。这些实验并不构成对就绪清理、
